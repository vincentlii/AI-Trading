# RAG接入原则

结论：RAG 只应检索经过分层和标注的知识，避免把原始研究、临时结论和当前实现混在一起。

## 分层

| 层 | 内容 | RAG 权重 |
| --- | --- | --- |
| 权威事实 | 根目录核心文档、代码入口、ADR | 高 |
| 状态摘要 | Vault 驾驶舱、当前阶段、完成度 | 高 |
| 策略卡 | 策略族、实现状态、风险 | 中高 |
| 原始研究 | `交易系统知识/` 长文档 | 中低，需摘要后使用 |
| 临时工作台 | 今日任务、草稿 | 低或不纳入 |

## 分块规则

- 一个文件只表达一个主题。
- 先结论，再依据。
- 表格优先用于状态和对比。
- 每张策略卡必须标注 `implemented` 或 `research_only`。
- proposal、复盘、ADR 必须保留状态字段。

## 不纳入 RAG

- `.obsidian/`
- `.claude/`
- `.claudian/`
- API key、secret、账户信息。
- 未验证的散文式复盘。
