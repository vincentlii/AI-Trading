# 待补齐清单

结论：本页是后续计划的唯一长期待执行清单；根目录规划文档只做入口，不再维护另一份正文。

## 使用规则

- `P6 模拟盘前必须补齐` 是进入正式 P6 模拟盘的 gate；LR formal research candidate 不自动进入 live path。
- `P1-P5 进阶增强` 是后续完善 backlog，默认不阻塞 BTC/ETH paper v1，除非单项被提升为 gate。
- 若某阶段先实现 MVP，MVP 外的完整功能、增强项和暂缓能力必须同步写入本页，不能只靠上下文记忆保留。
- 已完成事项必须从本页移出，并记录到 [[里程碑日志]] 或 [[当前完成度]]。
- 新任务优先写入本页，再由阶段页引用，避免散落在多个页面。

## P6 模拟盘前必须补齐

- 默认运行 `scripts/check_p6_gate.py` 必须通过后，才允许进入正式 P6 模拟盘观察。
- LR Restricted Variant B 若进入模拟盘观察，必须保持 `live_trading_enabled=false`，并确认 full-audit、robustness、exposure restriction、final regression baseline 和人工审批均无阻断。
- 新策略进入 formal candidate 前，必须通过 Research Pipeline 的 full-audit、no-lookahead、metric recompute、robustness、exposure restriction 和 regression baseline。

## Research Pipeline 后续复用

- 优先选择一个下一策略验证统一 pipeline 复用性，不要同时扩张多个策略。
- 候选方向：`trend_continuation`、`breakout_pullback`、`stopping_volume_retest`。
- 后续策略不得复制 PR11A-PR11H 临时 stage / PR 脚本流；应使用 strategy adapter、full-research pipeline、full-audit gate、robustness report 和 proposal report。
- 任何 proposal / diagnostic / summary row 不得进入 performance metrics；收益指标只能来自 `row_type=closed_trade`。
