# 项目总体架构

结论：本项目是研究优先的量化交易系统，核心由确定性交易热路径、只读诊断看板、paper 模拟盘和 Agent 慢路径组成。策略只生成标准信号，风控是订单前唯一闸门，Agent 只读取日志、报告和 proposal，不进入买卖决策热路径。

## 项目定位

项目面向加密资产、黄金相关资产和未来非加密资产研究，当前重点是历史回测、参数 proposal、诊断看板、paper 模拟盘前验证和复盘协作。

真实交易接口默认关闭。所有执行能力必须先服务研究、回测、模拟盘和复盘，不构成投资建议。

## 总体分层

| 层 | 职责 | 主要入口 |
| --- | --- | --- |
| 数据层 | 行情获取、历史 K 线仓库、标的映射、数据质量和覆盖率 | `trading_system/data/` |
| 指标层 | 可复用趋势、波动、量价和第三方指标校验 | `trading_system/indicators/` |
| 策略层 | 策略接口、策略注册、标准信号和解释载荷 | `trading_system/strategies/` |
| 配置层 | 正式 preset、risk、cost、asset、strategy 配置和 proposal 管理 | `trading_system/config/`, `configs/` |
| 风控层 | 仓位、止损、止盈、熔断、成本和订单审批 | `trading_system/backtest/risk.py` |
| 回测层 | 信号扫描、无前瞻撮合、批量回测、排名和 proposal 验证 | `trading_system/backtest/` |
| 诊断层 | 信号漏斗、拒绝原因、Near Miss、P6 gate | `trading_system/diagnostics/` |
| 报告层 | 回测表现、成本压力、回测运行记录、可选第三方报告 adapter | `trading_system/reports/` |
| 模拟盘层 | paper 行情事件、虚拟成交、持仓、权益和 ReviewLog | `trading_system/simulation/` |
| 看板层 | 本地 Streamlit 只读展示和中文呈现 | `app.py`, `trading_system/dashboard/` |
| Agent 慢路径 | 解释、复盘、红队、日报周报、参数 proposal | `AI Trading/07_Agent协作/`, `configs/proposals/` |

## 核心调用链

### 交易热路径

```text
MarketData
-> MarketRegime
-> PriceActionSetup
-> VolumePriceConfirmation
-> StrategySignal
-> RiskDecision
-> SimulatedOrder / VirtualOrder
-> PositionState
-> EquityCurve / ReviewLog
```

热路径必须确定性、可测试、可复现。LLM、Agent、复盘结论和 proposal 不得直接改变热路径行为。

### 数据下载与质量检查

```text
scripts/download_okx_history.py
-> OkxCliMarketData
-> OkxHistoryDownloader
-> DuckDbCandleRepository
-> check_repository_symbol_bar
```

数据层负责把交易所公开行情转成项目内部 candle 结构，写入 DuckDB 历史仓库，再由质量检查和覆盖率模块判断是否满足回测、诊断或 P6 gate 要求。

### 回测扫描与执行

```text
configs/presets/*.toml
-> load_backtest_preset
-> BacktestRollingScanner
-> Strategy.generate_signals
-> SignalOrderAdapter
-> RiskEngine
-> BacktestExecutionEngine
-> BacktestBatchRunner
```

回测入口读取正式 preset，按标的和周期滚动扫描 confirmed K 线。策略生成 `StrategySignal` 后，由 adapter 转为 `OrderIntent`，再交给 `RiskEngine` 审批，最后由执行引擎撮合、记录权益曲线和汇总结果。

SWAP proposal 另有分层缓存路径：

```text
confirmed candles
-> context_features cache
-> raw_candidates cache
-> filter_replay
-> contract risk diagnostics
-> execution_replay
-> proposal diagnostics report
```

该路径用于调参诊断和大窗口回测加速，不替换确定性回测热路径。参数阈值变化优先复用 context 和 raw candidates，只重跑 filter replay；成本、funding、出场和 same-bar 变化重跑 execution replay。

### P5 只读看板

```text
app.py
-> build_default_dashboard_snapshot
-> backtest / data / diagnostics / reports / simulation review_log
-> dashboard.presentation
-> Streamlit UI
```

看板只读读取配置、回测、数据质量、诊断、报告和 paper review log。看板不得直接写入正式配置，不触发真实交易，不自动应用 proposal。

### P6 paper 模拟盘

```text
MarketEvent
-> paper_inputs_from_market_events
-> PaperTradingEngine
-> SignalOrderAdapter
-> RiskEngine
-> PaperBroker
-> ReviewLogEntry
-> JSONL ReviewLog
```

P6 paper 复用 P4 的信号、风控和执行模型，只新增模拟盘事件循环、虚拟订单、虚拟持仓和结构化复盘日志。

### Agent 慢路径

```text
Reports / ReviewLog / Diagnostics
-> Agent review / red-team / explanation
-> ParameterProposal
-> validate_parameter_proposal
-> manual review
-> formal config candidate
```

Agent 可以读取报告、日志和诊断结果，可以生成 proposal，但 proposal 不自动生效。正式配置变更必须经过回测验证、人工确认，并作为新的配置版本进入 Git。

## 核心接口边界

| 接口 | 所在文件 | 边界 |
| --- | --- | --- |
| `Strategy`, `StrategySignal` | `trading_system/strategies/base.py` | 策略只产出标准信号和解释载荷，不管理账户、不下单 |
| `RiskEngine`, `RiskDecision` | `trading_system/backtest/risk.py` | 风控是订单前唯一闸门，负责仓位、熔断、成本和拒绝原因 |
| `BacktestExecutionEngine`, `BacktestRunResult` | `trading_system/backtest/execution.py` | 执行回测撮合、出场、成本、权益曲线和结果汇总 |
| `CandleRepository`, `DuckDbCandleRepository` | `trading_system/data/history.py` | 封装历史 K 线存取，上层不直接依赖 DuckDB 表结构 |
| `PaperTradingEngine`, `ReviewLogEntry` | `trading_system/simulation/paper.py` | 连接标准信号、风控、虚拟成交和结构化复盘日志 |
| `DashboardSnapshot` | `trading_system/dashboard/panel.py` | 看板数据聚合边界，UI 不直接拼装底层业务逻辑 |
| `BacktestPresetConfig` | `trading_system/config/loader.py` | 正式回测配置的结构化表示 |
| `ParameterProposal` | `trading_system/config/proposals.py` | 参数建议载体，不等同正式配置 |

## 文档维护规则

`AI Trading/` 是长期事实唯一落点。聊天、临时报告、根目录薄入口都不能作为长期事实来源。

需要更新本页的情况：

- 新增或删除 `trading_system/` 下的生产模块。
- 新增或删除 `configs/` 下的正式配置类型。
- 新增或删除 `scripts/` 下的核心命令入口。
- 新增或删除 `app.py` 级别的用户可见入口。
- 策略、风控、回测、模拟盘、看板、Agent 慢路径之间的调用方向发生变化。
- 新增长期权威文档，且会影响项目接手、架构理解、开发约定或验证方式。

不需要更新本页的情况：

- 只新增或修改测试文件。
- 只更新缓存、临时数据、运行产物或 Obsidian 工作区状态。
- 只修改一次性报告或未纳入长期知识源的草稿。
- 只改文案且不改变模块职责、入口和调用关系。
