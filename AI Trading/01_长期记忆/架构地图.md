# 架构地图

结论：系统分为确定性热路径、Research Pipeline 慢速研究路径和 Agent 慢路径；正式执行边界仍由 RiskEngine 与人工审批守住。

完整模块职责、核心文件清单、调用关系和维护规则见 [[项目总体架构]]。

## 热路径

```text
MarketRegime -> PriceActionSetup -> VolumePriceConfirmation -> RiskDecision -> SimulatedOrder -> PositionState
```

## 分层

| 层 | 职责 | 入口 |
| --- | --- | --- |
| 数据层 | 行情、标的物、交易所映射、质量状态 | `trading_system/data/` |
| 指标层 | 可复用指标和特征 | `trading_system/indicators/` |
| 策略层 | 标准信号和解释载荷 | `trading_system/strategies/` |
| 风控层 | 仓位、止损、止盈、熔断 | `trading_system/backtest/risk.py` |
| 回测层 | 无前瞻撮合、交易日志、权益曲线 | `trading_system/backtest/` |
| Research Pipeline | 策略研究、artifact、audit、robustness、proposal-to-formal | `research_pipeline/` |
| 看板层 | 本地只读展示 | `app.py`, `trading_system/dashboard/` |
| Agent 慢路径 | 解释、复盘、红队、proposal | [[Agent协作总览]] |
| 归档层 | 历史草稿、一次性报告、原始研究资料 | `AI Trading/99_归档/` |

## 当前架构重点

- P4/P5 已形成回测和只读看板基础。
- P6 需要新增模拟盘事件循环和结构化日志。
- LR Restricted Variant B 已完成 formal research candidate 收口，但仍不是 live trading strategy。
- Research Pipeline 已收敛到 hardened：strategy adapter / registry / CLI、RunManifest、artifact contract、audit profile、artifact reader / index、research run registry、candidate schema / lineage、Full Audit Gate、metric recompute、no-lookahead audit、edge / sizing / robustness analytics 和 legacy wrapper compatibility。
- Full Audit Gate 是 robustness 和 proposal-to-formal 前置门槛，performance metrics 只能来自 `row_type=closed_trade`，且 no-lookahead 必须验证时间顺序。
- 原宽泛 `trend_continuation` 已标记为 `strategy_definition_refactor_needed`；趋势延续策略族拆为 `compression_expansion`、`breakout_pullback`、`trend_pullback`。
- `compression_expansion` 已完成 proposal-only research validation、expansion diagnostics、cross-run artifact reuse 和 Full Audit Gate 验证，当前为 diagnostic candidate，不是 formal candidate。
- Agent 只能读取日志与报告，不进入买卖决策热路径。
- 后续若新增核心模块、核心文件、核心入口、核心配置或模块调用关系变化，必须同步更新 [[项目总体架构]]。

## 文档维护重点

- `AI Trading/` 是长期事实唯一落点；根目录文档只保留薄入口。
- 新增长期事实前先检查是否已有同主题页面，能合并则合并，不能合并再新增。
- 历史草稿、一次性报告和原始研究资料先提炼长期结论，再移动到 `AI Trading/99_归档/`。
- 归档材料不代表当前实现能力；当前能力以 [[项目事实库]]、策略页、回测/风控页和代码测试为准。

## Trend Continuation Shared Setup Engine

`trading_system/strategies/trend_price_volume_v1/trend_continuation_core.py` 是趋势延续策略族共享研究内核。

长期边界：

- 共享阶段为 structure zone、breakout lifecycle、pullback health、relaunch、structural stop、target/cost-adjusted tradeability。
- breakout 只作为背景事件；只有 `failed_breakout` 可在 lifecycle 阶段直接淘汰。
- adapter 负责声明 setup 专属 variants 与诊断阶段，Research Pipeline 负责 event artifact、manifest、reuse、audit 和报告。
- `core_event_rows.jsonl` 是 diagnostic-only artifact；不得进入收益统计。
- closed_trade 必须保留 `level_id`、`breakout_event_id`、`lifecycle_event_id` 和完整时间顺序。
- 共享内核版本必须进入 candidate cache fingerprint，版本变化时拒绝复用旧 raw candidate cache。
