# P5.1数据覆盖与信号诊断

结论：P5.1 的目标是解释“为什么没有信号”，不是美化看板，也不是提前进入 P6。

## 数据覆盖目标

| 阶段 | 目标 |
| --- | --- |
| regime 最低计算 | 趋势周期至少 201 根 confirmed K 线 |
| 最低可运行 | 每个 `symbol/bar` 至少 300 根 |
| 初步诊断 | 每个 `symbol/bar` 尽量达到 1000 根 |
| 正式回测 | BTC/ETH 至少覆盖 1-3 年 |

高周期优先级：`1D -> 4H -> 1H -> 15m -> 5m`。

## 当前能力

- `trading_system.data.coverage` 输出每个 `symbol/bar/profile` 的覆盖状态。
- `trading_system.diagnostics.signal_funnel` 输出信号漏斗卡点。
- P5 看板新增 `诊断` tab，展示数据覆盖、profile 覆盖和信号漏斗。
- `scripts/download_okx_history.py` 支持：
  - `--target-min-candles`
  - `--start-date`
  - `--quality-check-after-download`

## 信号漏斗阶段

- `data_insufficient`
- `regime_not_computable`
- `regime_rejected`
- `price_action_rejected`
- `volume_price_rejected`
- `target_space_insufficient`
- `risk_rejected`
- `approved_signal`

## 推荐命令

先补高周期诊断级数据：

```powershell
.\.venv\Scripts\python scripts\download_okx_history.py --symbols BTC-USDT ETH-USDT --bars 1D 4H 1H --limit 300 --max-pages 20 --target-min-candles 1000 --quality-check-after-download
```

再补中低周期：

```powershell
.\.venv\Scripts\python scripts\download_okx_history.py --symbols BTC-USDT ETH-USDT --bars 15m 5m --limit 300 --max-pages 20 --target-min-candles 1000 --quality-check-after-download
```

正式回测前按起始日期补齐：

```powershell
.\.venv\Scripts\python scripts\download_okx_history.py --symbols BTC-USDT ETH-USDT --bars 1D 4H 1H 15m 5m --limit 300 --max-pages 200 --start-date 2023-01-01 --quality-check-after-download
```

## 边界

- 不通过放宽策略条件来制造信号。
- 不在没有诊断解释时直接进入 P6 模拟盘。
- 不把 smoke test 下载参数当作正式回测数据准备。
- 不绕过 confirmed K 线过滤和数据质量检查。
