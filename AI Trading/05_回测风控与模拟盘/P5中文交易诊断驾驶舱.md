# P5中文交易诊断驾驶舱

结论：P5 已从工程表格后台升级为中文交易诊断驾驶舱，但仍是只读看板，不修改策略、风控、回测主口径或 proposal 审批机制。

## 页面结构

- 首页
- 信号诊断
- 策略排名
- 风控分析
- 完整回测
- 绩效报告
- 数据质量
- Proposal 队列
- 系统说明

## 双口径展示

- 近期诊断概况：最近 200 entry window，用于解释当前为什么没有信号、候选卡在哪一层。
- 完整回测结论摘要：P4 完整回测主口径，用于展示策略长期表现。

近期 200 window 不替代 P4 完整回测。首页可以同时展示二者，但必须明确标注口径差异。

## 信息架构原则

历史看板草稿已归档。长期保留以下设计结论：

- 看板定位是交易系统诊断驾驶舱，不是营销页、实盘交易终端或纯工程表格后台。
- 首页优先回答系统是否可运行、数据是否可靠、为什么没有信号、主要卡点在哪里、哪些候选最接近通过。
- 信号诊断主线应串起数据覆盖、profile 覆盖、信号漏斗、量价拒绝、风控拒绝、Near Miss 和 proposal。
- 卡片用于摘要，图表用于趋势和分布，表格用于详情；大表格、路径、长 `reason_codes` 和英文工程字段应下沉到详情或展开区。
- 界面默认中文展示；英文字段名可保留在 tooltip、说明或调试展开区，方便 Agent 和代码对接。
- Proposal 区域必须强调只读、待验证、待回测、待人工确认，不提供自动应用入口。

## 完整回测加载规则

- 首页只展示完整回测摘要，不默认加载完整明细。
- `完整回测` tab 通过展开区延迟加载 ranking rows 与 performance rows。
- 后续优先演进为 P4 跑完后保存 artifact，P5 直接读取 artifact 摘要和明细。

## 展示层依赖边界

- Plotly 只用于 P5 展示层图表，例如信号漏斗、拒绝原因排行、止损/ATR 分布。
- Streamlit 会同时构建所有 tab；所有 `st.plotly_chart` 必须传稳定唯一 `key`，避免相同图表在不同 tab 触发 `StreamlitDuplicateElementId`。
- Plotly 不进入 `StrategySignal`、`RiskEngine`、无前瞻撮合、`SimulatedOrder`、`PositionState`、`TradeLog`、`ReviewLog` 或 proposal 审批机制。
- QuantStats / empyrical 后续仍只作为报告层辅助，不覆盖项目 BacktestSummary 与 ranking 主口径。

## Proposal 队列边界

- P5 只读展示 Proposal 状态。
- 不提供自动应用按钮。
- 不允许 LLM/Agent 绕过 proposal 队列或直接修改正式配置。
