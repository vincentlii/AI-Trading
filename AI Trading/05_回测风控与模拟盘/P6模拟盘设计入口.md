# P6模拟盘设计入口

结论：P6 应复用 P4 的信号、风控和执行模型，新增模拟盘事件循环与结构化日志，而不是重写交易路径；当前已完成 P6 gate 能力 v1，但正式模拟盘仍需通过 `scripts/check_p6_gate.py`。

## 目标链路

```text
PublicMarketData -> StrategySignal -> RiskDecision -> VirtualOrder -> PositionState -> EquityCurve -> ReviewLog
```

## 当前最小 v1

入口：

- `trading_system/simulation/paper.py`
- `trading_system/simulation/events.py`
- `trading_system/simulation/review_log.py`
- `trading_system/diagnostics/p6_gate.py`
- `scripts/check_p6_gate.py`
- `tests/test_simulation_paper.py`

已完成：

- `PaperTradingEngine` 接收标准 `StrategySignal` 和 execution candles。
- 复用 `SignalOrderAdapter` 将信号转换为 `OrderIntent`。
- 复用 `RiskEngine` 做审批和拒绝。
- `PaperBroker` 为 approved order 生成虚拟 fill 和 `PositionState`。
- `ReviewLogEntry` 记录信号、adapter 拒绝、风控拒绝、订单、成交、持仓、退出和权益事件。
- open positions 会回灌下一次 `AccountState`，用于模拟盘前风险一致性校验。
- OKX public candles polling 和历史回放事件源已接入。
- JSONL ReviewLog 持久化已接入。
- 虚拟权益曲线、退出事件和持仓关闭已接入。
- P5 看板已新增 P6 Paper 只读 tab。

仍待验收：

- BTC/ETH formal backtest 数据覆盖需要补齐。
- 当前正式配置近期信号全部因 `stop_distance_too_far` 被 RiskEngine 拒绝，尚无 closed trades 支撑成本后 R 和失败归因验收。
- 需要先进入回测复盘和参数 proposal 阶段，验证后再重新运行 `scripts/check_p6_gate.py`。

## 设计原则

- 只读公开行情。
- 只生成虚拟订单。
- 虚拟订单必须来自标准信号和 RiskEngine。
- 结构化日志是 Agent 慢路径唯一输入。
- 不引入真实交易权限。

## 核心对象建议

| 对象 | 职责 |
| --- | --- |
| MarketEvent | 行情事件 |
| SignalEvent | 策略信号事件 |
| RiskEvent | 风控通过或拒绝 |
| VirtualOrderEvent | 虚拟订单 |
| PositionEvent | 虚拟持仓变化 |
| EquityEvent | 虚拟权益变化 |
| ReviewEvent | 复盘和解释输入 |
