## 已完成的立即补齐

- 统一 P6 状态口径，避免把“准备进入 P6”误读为“已进入模拟盘”。
- 澄清 `trend_price_volume_v1` 只是 OHLCV confirmed K 线基础上的 v1 子集，不等于完整 PA+VPA/SMC/VSA 策略。
- 明确当前 v1 只依赖 OHLCV、多周期 K 线、confirmed K、基础趋势/波动/量价指标和 P5/P5.1/P5.2 诊断。
- 明确 OB/FVG 生命周期、ToD RVOL、AVWAP、CVD/OI、订单簿、taker imbalance、宏观事件过滤是后续增强，不是当前入场依赖。
- 固化趋势门控：04 周期趋势可作为硬门控；01 周期趋势更适合作为确认、软过滤或风险降权。
- 分开描述入场逻辑、失效条件、止损逻辑、出场逻辑和拒绝原因，避免把诊断项误写成交易条件。
- 保留 P5.2 的量价拒绝细分、风控拒绝细分、Near Miss、`stop_distance/ATR` 分布作为模拟盘前诊断验收。

## P6 目标

建立公开行情到虚拟订单、虚拟持仓、虚拟权益曲线的模拟盘事件循环，并输出可供复盘 Agent 读取的结构化日志。

## P6 边界

| 包含 | 不包含 |
| --- | --- |
| 公开行情读取 | 真实账户交易 |
| 虚拟订单 | API secret 管理 |
| 虚拟持仓 | 自动实盘下单 |
| 虚拟权益曲线 | Agent 直接改参数 |
| 信号解释 | 绕过 RiskEngine |
| 风控拒绝解释 | 未审批 proposal 生效 |
| 复盘报告 | 实盘权限入口 |

## 建议拆分

1. P6 gate 能力：事件源、JSONL ReviewLog、paper 持仓生命周期、权益曲线、position-aware 回测、无前瞻审计和 P5 paper tab 已接入。
2. 当前阻塞：BTC/ETH formal backtest 数据覆盖不足。
3. 当前阻塞：正式配置近期信号全部因 `stop_distance_too_far` 被 RiskEngine 拒绝，尚无 closed trades 可用于成本后 R 和失败归因验收。
4. 下一步：先做回测复盘和参数 proposal，经回测验证后再重新运行 `scripts/check_p6_gate.py`。
5. P1-P5 进阶增强：统一按 [[待补齐清单]] 排期，默认不阻塞 BTC/ETH paper v1。

## 验收标准

- 模拟盘只读公开行情，不需要真实交易权限。
- 虚拟订单和虚拟持仓只来自标准信号与 RiskEngine。
- 多周期输入只使用 confirmed K 线，无前瞻偏差审计通过。
- 结构化日志字段稳定，可被 Agent 和后续 RAG 使用。
- `scripts/check_p6_gate.py` 默认口径通过。
- 所有参数建议仍进入 proposal 队列，不自动落地。
